# Stream Kit 统一服务端预发布版 2026-11-09.3

Windows x64 与 Ubuntu 24.04 amd64 的单文件安装包均来自源码 `df7cd87b3352a638aa3a6aa7073d39074c02a43c`，包含管理服务、Sunshine 和媒体网关。两个原始安装包、Windows 精确安装验收及 Linux 初始化检查已核对；发布流程复用这些产物。发布不会自动更新已有部署。

## 本版变化

- 统一区分可恢复的连接租约到期与已终结的观看连接。租约恢复保留原会话和连接身份；收到确定终态后关闭本地输入、麦克风与 RTC，不自动重新唤起应用。
- 观看端停止操作共用同一清理过程；正常关闭按媒体资源、连接的顺序清理，迟到响应与旧凭据不覆盖新连接。
- 观看端明确显示“观看已结束”，控制权和麦克风权限随同一生命周期关闭。普通控制权通知使用正常信息配色，警告与错误保持各自等级。
- 永久观看链接仍可由用户再次主动进入；连接结束不会自动轮换链接。Android APK 独立签名和发布，不包含在服务端安装器中。

## 安装和访问

Windows 管理员终端静默安装：

```powershell
.\stream-kit-preview-df7cd87b3352-windows-amd64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART
```

Ubuntu 24.04 将 `RENDER_USER` 替换为实际拥有图形、音频会话的用户：

```sh
sudo bash stream-kit-preview-df7cd87b3352-ubuntu24.04-amd64-setup.run --user RENDER_USER
```

Windows 安装器创建自动启动的 `StreamKitOrchestrator` 系统服务，由其管理渲染端和网关工作进程。渲染需要登录后的桌面会话；安装器不设置自动登录，也不自动重启电脑。部署主机无需另装 Node.js/npm，不依赖 VB-CABLE。Example、探针、测试 CA、测试凭据、Playwright、模拟器和 SDK 不进入客户运行安装包。

首次在服务器本机打开 `http://127.0.0.1:9000`，从受保护的运行配置取得唯一管理员凭据。局域网客户端使用服务器的局域网地址；远程麦克风需要配置监听、媒体地址与可信 HTTPS，再从应用页复制永久观看链接。配置 `server.lan_tls` 后，后续地址变化沿用原部署 CA 更新服务证书，保存配置并重启服务生效；数字 IP 书签需相应更新地址部分。

已有安装、服务和运行数据受保护，本版安装器不提供原位升级。部署说明见 [Windows](https://github.com/bei612/stream-kit/blob/main/deploy/windows/README.md)、[Linux](https://github.com/bei612/stream-kit/blob/main/deploy/linux/README.md) 和[局域网地址配置](https://github.com/bei612/stream-kit/blob/main/docs/lan-address-configuration.md)。
