# Stream Kit 统一服务端预发布版 2026-11-10.2

Windows x64 与 Ubuntu 24.04 amd64 安装包均来自 `3d4f248c00cce003e4649a1d3e6b5f907dcfee39`，包含管理服务、Sunshine 与媒体网关。复用已构建、已验收的原始安装包发布，不重新构建。发布不会自动更新已有部署。

## 本版修复

- 控制权通知归属当前串流生命周期，结束、失去有效授权或重新连接时清除旧提示，避免结束页面继续显示上次撤权通知。
- 连接进度使用用户可读的状态文案，技术日志保留在诊断位置；控制者、观看者与观看结束状态使用统一翻译目录。
- 保留确定结束后停止输入、麦克风、RTC 与自动恢复的行为，永久链接仍可由用户主动再次进入。

## 安装与访问

Windows 管理员终端静默安装：

```powershell
.\stream-kit-preview-3d4f248c00cc-windows-amd64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART
```

Ubuntu 24.04 将 `RENDER_USER` 替换为实际拥有图形、音频会话的用户：

```sh
sudo bash stream-kit-preview-3d4f248c00cc-ubuntu24.04-amd64-setup.run --user RENDER_USER
```

Windows 安装器注册 `StreamKitOrchestrator` 自动启动系统服务，由其管理渲染端与网关。渲染需要登录后的桌面会话；安装器不设置自动登录、不自动重启电脑。宿主机无需另装 Node.js/npm，不依赖 VB-CABLE。Example、测试声源、探针、开发 CA、测试凭据与调试工具不进入客户安装包。

首次在服务器本机打开 `http://127.0.0.1:9000`，从受保护的运行配置取得唯一管理员凭据。局域网客户端使用服务器局域网地址；远程麦克风需配置可信 HTTPS、监听与媒体地址，再从应用页复制永久观看链接。LAN TLS 地址更新沿用原部署 CA，保存配置并重启服务生效；数字 IP 书签需要更新地址部分。

本版安装器保护已有安装与数据，不提供通用原位升级。已有部署请参阅 [Windows 部署说明](https://github.com/bei612/stream-kit/blob/main/deploy/windows/README.md)、[Linux 部署说明](https://github.com/bei612/stream-kit/blob/main/deploy/linux/README.md)及[地址配置](https://github.com/bei612/stream-kit/blob/main/docs/lan-address-configuration.md)。Android APK 独立签名与发布，不包含在服务端安装器中。

## 验收边界

这是预发布版。Windows 服务重启不等于整机重启；音频默认设备基线为空，不外推已有非空默认设备的保持能力。卸载后检查保留了配置文件，未独立覆盖应用文件与数据库保留场景。

浏览器验收不代表本机 Windows 已更新、Android 音频、真人语音、目标键鼠输入或实际宿主机 IP 切换通过。正式 APK 的音频缺口仍单独保留，未以本版结果代替。
