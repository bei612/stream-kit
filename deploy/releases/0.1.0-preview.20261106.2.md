# Stream Kit 统一服务端预发布版 2026-11-06.2

Windows x64 与 Ubuntu 24.04 amd64 安装包来自同一源码版本 `d36cead6fd856925b283daddcc4af6cd1cdb7dd0`。本版修复输入权限移交和异常控制报文处理，仍属于预发布版本。

2026-11-07 补充：本版随后确认存在原生 HTTPS / HTTP/2 地址生成缺陷，远端观看页可能收到内部 `127.0.0.1` 控制地址。源码 `00fe4953` 已修复，新 Linux 安装包已通过独立局域网地址切换及 WebRTC 恢复；匹配的 Windows 安装包仍在构建，替代版本尚未发布。本页附件仍为原 `d36cead6` 文件，不包含修复。参见[缺陷与修复证据](../../docs/evidence/lan-http2-address-20261107.json)。

输入在进入队列时绑定控制权代次，转发前再次核对，避免控制权在排队期间移交后重新授权旧输入。输入通道关闭、队列满或接收任务异常退出时，结束对应连接并统一释放已按下的输入；连接退出时取消所属收发任务。

同时修复控制报文截断、输入长度下溢和超长文本复制引发的崩溃路径。Windows/Linux 原生网关单元测试、格式检查和严格 Clippy 检查已通过，覆盖输入撤权、队列容量、任务生命周期与畸形报文。

后续复用本版二进制完成独立端到端验收：[Windows Web 实际输入与旧控制报文拒绝](../../docs/evidence/windows-stream-input-20261106.json)，以及 [Linux 渲染端与官方 Android 模拟器/Web 的输入、移交、撤销及重新授权](../../docs/evidence/android-stream-input-20261107.json)。结论来自目标程序实际收到的事件，未重建安装包；独立环境结果不代表本机 Windows 输入问题已解决。

本安装文件已在独立 Windows CI 环境完成静默安装、管理员登录、安装程序创建自动启动服务、网关及服务重启恢复、原生音频收发、默认音频设备保留，以及卸载和数据保留验收；未进行整机重启。Linux 安装包已通过原生解包、用户服务离线启用、初始化及已有数据保护检查，未进行 Linux 真机串流验收。两端文件大小与 SHA-256 均已核对。

## 安装与访问

Windows 管理员终端静默安装：

```powershell
.\stream-kit-preview-d36cead6fd85-windows-amd64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART
```

Ubuntu 24.04 使用实际运行图形、音频会话的用户名替换 `RENDER_USER`：

```sh
sudo bash stream-kit-preview-d36cead6fd85-ubuntu24.04-amd64-setup.run --user RENDER_USER
```

安装程序统一部署 Orchestrator、Sunshine、媒体网关与 Web 管理页并配置启动关系。渲染进程依赖可用的用户图形会话；不启用系统自动登录，不自动重启电脑。部署主机无需另装 Node.js，不依赖 VB-CABLE。原位升级能力不在已验证范围。

默认本机管理入口为 `http://127.0.0.1:9000`。其他设备使用服务器可达的局域网地址。详细步骤见 [Windows 部署说明](https://github.com/bei612/stream-kit/blob/d36cead6fd856925b283daddcc4af6cd1cdb7dd0/deploy/windows/README.md)和 [Ubuntu 安装说明](https://github.com/bei612/stream-kit/blob/d36cead6fd856925b283daddcc4af6cd1cdb7dd0/deploy/linux/INSTALL.md)。附件包含两端安装包、源码清单、SHA-256 和 SPDX SBOM。
