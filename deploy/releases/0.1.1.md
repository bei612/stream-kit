# 云端渲染 0.1.1

本版提供 Windows 11 x64 和 Ubuntu 24.04 amd64 服务端安装器，以及原生 Android 客户端。Web 和 Android 可以观看同一个应用串流。管理员可实时移交或收回操作与麦克风权限。发布标签、安装器清单和 `android-provenance.json` 记录同一源码版本，Android 版本号和签名摘要见 APK 清单。

## 本版改进

- 局域网地址变化后，服务沿用已有部署 CA 更新管理端和媒体网关的 HTTPS 身份。直连的受管 WebRTC 会话使用信令连接实际到达的 IPv4 地址承载媒体。启用固定观看主机名后，服务器换 IP 时，能解析并访问该主机名的设备继续使用原链接。已有数字 IP 的书签可一次换成固定主机名并保留观看密钥。已配置固定 NAT 映射的部署继续使用原映射。
- 启用托管部署 CA 后，管理服务使用该 CA 验证本机 HTTPS 媒体网关。签名状态同步、配置查询、音频设备查询和同源健康检查共用这一信任配置。
- 应用详情的永久观看链接操作和采集能力说明随管理端语言切换。上传直接写入暂存文件，60 秒无数据才会超时。添加应用页面显示服务器当前生效的单包和解压总量上限，默认为 50 GiB 和 50 GiB。

## 安装与访问

1. **Windows 服务端**使用下载页中以 `windows-amd64-setup.exe` 结尾的统一安装器。静默参数为 `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART`，安装系统服务需要管理员权限。控制服务随 Windows 启动，媒体网关和 Sunshine 随已配置用户的桌面会话启动。首次安装若返回 `3010`，按维护窗口手动重启 Windows，登录该用户后检查三组件状态。
2. **Ubuntu 服务端**使用下载页的 Ubuntu 24.04 安装器，运行 `sudo bash INSTALLER.run --user RENDER_USER`，替换实际文件名和渲染用户。
3. **管理后台**首次安装后可在服务端打开 `http://127.0.0.1:9000/`。从其他设备访问时，按局域网配置文档启用 HTTPS、让客户端信任部署 CA，再访问 LAN 地址的 `9000` 端口。登录后登记程序，并在应用详情复制永久观看链接。
4. **Android 客户端**安装 `stream-kit-android-0.1.1.apk` 后导入永久观看链接。Web 客户端可以直接打开同一链接。在「渲染会话」获得控制权后，客户端可操作画面并按需打开麦克风。

下载页的 `SHA256SUMS.txt` 覆盖 Windows 安装器、构建清单和 SPDX 源码依赖清单。`Android-SHA256SUMS.txt` 覆盖 APK、构建来源、依赖清单及许可证分发包。通过 `Linux-SHA256SUMS.txt` 校验 Ubuntu 安装器及清单。一台渲染宿主机同时服务一个渲染应用。对既有 Windows 部署进行维护前，请保留应用数据、配置和部署 CA。

访问、维护、兼容性和对应版本证据见[使用文档](https://github.com/bei612/stream-kit/blob/main/docs/README.md)、[局域网地址配置](https://github.com/bei612/stream-kit/blob/main/docs/lan-address-configuration.md)和[发布基线](https://github.com/bei612/stream-kit/blob/main/docs/release-status.md)。
