# Stream Kit 统一服务端预发布版 2026-11-10.4

本版修复管理页在已接收串流时偶发显示“状态待确认”的问题。Windows x64 与 Ubuntu 24.04 amd64 统一安装包使用源码 `571295af7c106ca5080b7a7510ffe62715b90de6`，包含管理服务、Sunshine 和媒体网关。发布流程校验原始构建来源、两平台安装包 SHA-256 和精确 Windows 安装验收；复用原始文件，不在发布时重新构建。

## 本版变更

- 管理页通过一个禁止缓存的响应读取当前会话、签名媒体回执及服务器采样时间，避免独立轮询缓存版本错配。
- 运行状态按服务器时间与快照实际经过时间老化，避免客户端时钟偏差或旧重绘时间误判；保持精确版本匹配、原观测期限和权限校验。
- 心跳也会增加会话版本，页面改用“会话状态已同步 / 等待网关同步”和“会话版本 / 网关确认版本”，不再将心跳称为配置修改。未配置网关仍可查看真实会话，并明确提示媒体不可用。

当前单宿主机同一时刻支持一个应用串流，多个客户端可共同观看，由唯一控制者操作并发送麦克风；不支持三个不同应用同时独立串流。永久入口、客户端授权和短时媒体票据的协议保持不变。

## 安装与访问

Windows 管理员终端静默安装：

```powershell
.\stream-kit-preview-571295af7c10-windows-amd64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART
```

Ubuntu 24.04 将 `RENDER_USER` 替换为实际拥有图形、音频会话的用户：

```sh
sudo bash stream-kit-preview-571295af7c10-ubuntu24.04-amd64-setup.run --user RENDER_USER
```

Windows 安装器注册自动启动的 `StreamKitOrchestrator` 系统服务，由其管理渲染端和网关；渲染需要登录后的桌面会话。安装器不设置自动登录、不自动重启电脑。运行不要求宿主机另装 Node.js/npm，不依赖 VB-CABLE。Example、测试声源、探针、开发 CA、测试凭据和调试工具不随安装包交付。

首次在服务器本机打开 `http://127.0.0.1:9000`，从受保护的运行配置取得唯一管理员凭据。局域网使用服务器可达地址；远程麦克风需配置可信 HTTPS、监听和媒体地址，再从应用页复制永久观看链接。地址更新沿用原部署 CA，保存配置并重启服务生效；数字 IP 书签需要更新地址部分。

本版安装器保护已有安装和数据，不提供通用原位升级。现有部署参阅 [Windows 部署说明](https://github.com/bei612/stream-kit/blob/main/deploy/windows/README.md)、[Linux 部署说明](https://github.com/bei612/stream-kit/blob/main/deploy/linux/README.md)和[地址配置](https://github.com/bei612/stream-kit/blob/main/docs/lan-address-configuration.md)。Android APK [20261109.6](https://github.com/bei612/stream-kit/releases/tag/v0.1.0-android-preview.20261109.6)保持独立签名与发布，本次管理页修改不重新构建 APK。
