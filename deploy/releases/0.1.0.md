Stream Kit 0.1.0 提供 Windows / Ubuntu 24.04 amd64 统一服务端安装器和同源签名 Android APK，运行源码为 `f8ede8b2e933fb597e97dec999cceae9a3e614e1`。本版本复用已验收的原始构建字节，不在发布时重新构建。

一个管理后台统一登记本机程序或上传归档、配置桌面/指定程序采集、管理永久观看链接和客户端。一个应用串流供多个客户端观看，只有当前控制者可以操作和主动发送麦克风；声音可送到服务器录音端点，并与程序音一起广播。Web 和 Android 共用会话与权限，单管理员，不包含多用户账户系统。

本次修复持续视频帧元数据、失败连接及浏览器 reader 的释放，统一媒体队列、缓存、请求体和日志容量边界，应用操作锁随操作结束回收。默认 H.264 统一为 Web/Android 可共享的普通格式，解决 Web 先启动时选择 High 4:4:4 导致 Android 后加入失败的问题。实验性 auto 仍可能选择高阶格式，不承诺异构终端全部支持。

Windows 下载唯一的 `*-windows-amd64-setup.exe`，可使用 `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART` 静默安装；安装系统服务仍需 Windows 管理员权限/UAC。Ubuntu 下载唯一的 `*-ubuntu24.04-amd64-setup.run`，执行 `sudo bash INSTALLER.run --user RENDER_USER`，替换实际文件名及渲染桌面用户。安装器建立启动和组件恢复关系，宿主机无需另装 Node.js。生产包不包含 Example、测试探针、测试声源、开发 CA 或凭据，不依赖 VB-CABLE。Windows EXE 未使用商业发行者证书；分发的内核驱动签名已经核验。

Android 安装 `stream-kit-android-0.1.0.apk`（versionCode 1000015），沿用持久发行签名；导入管理员提供的 HTTPS 永久观看链接。私有 LAN 部署首次需要信任部署 CA，更换 IP 后通过服务配置更新身份，保留原 CA，不必重新编译 APK 或重装客户端 CA。数字 IP 书签需更新主机地址。Android 附带来源、依赖、许可证和 SBOM；其来源清单保留签名候选构建身份，发布复用相同 APK 字节。

本版已达到上述核心功能的发布条件，不意味着全部环境和整个 Goal 的验收已经结束。一台渲染主机同时运行一个应用串流，不支持多个应用并行隔离。共享 Windows 主机的实际整机重启和主网卡迁移完整恢复尚未验收；服务重启与独立 Linux 地址实验不替代它们。没有新版本 168 小时连续运行、物理设备声学或指定 UE 内部录音证明，不能承诺永不 OOM。已有四小时证据保留原版本，未重复长跑；Linux 模拟器历史音频负例仍保留。

已有安装不会因发布自动更新。维护前备份配置和数据，保留部署 CA、永久链接及管理员身份；Windows 通用自动原位升级和数据库自动降级未提供。完整操作、当前部署和验证范围见[长期文档](https://github.com/bei612/stream-kit/blob/main/docs/README.md)及[发布基线](https://github.com/bei612/stream-kit/blob/main/docs/release-status.md)。
