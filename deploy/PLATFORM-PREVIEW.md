# Windows 平台目录手工部署边界

客户首次安装使用统一 EXE；安装器已完成初始化和自动服务注册，不要再手工补初始化、注册 Sunshine 服务或添加开机项。正常使用见 [Windows 安装](windows/README.md)，运维见[部署手册](README.md)。

本文件仅说明开发者验证完整平台目录时的区别。当前发布是否包含虚拟音频驱动及验收状态以实际清单和[部署基线](../docs/release-status.md)为准；不能沿用旧候选“没有驱动、需 VB-CABLE 授权”的结论。

## 手工验证完整运行目录

1. 验证 `platform-manifest.json`、三个组件清单和 `orchestrator verify-platform DIRECTORY`，保留来源与摘要。
2. 将固定程序目录与受保护外部数据目录分开，使用当前 `init-platform` 原生初始化流程；不要把只生成控制配置的 `init-config` 当作完整平台安装。
3. 按实际桌面 SID/会话和端口准备运行配置、机器间凭据及必要音频。裸目录没有代替统一 EXE 完成所有驱动/服务安装的承诺。
4. 直接控制端运行与 SCM 服务运行是不同身份边界。手工验证不建立客户安装器已通过的证据，也不要在已有生产服务旁复用相同数据或端口。
5. 使用固定观看入口验证应用自动配对、真实画面、声音和控制权，结束清理仅本次创建的资源。

产品运行不需要 Node.js/npm 或编译器；本目录也不应包含 Example、probe、开发 CA 和测试数据库。附带商业发行者签名不是当前要求，内核驱动的签名校验仍适用。

## 更新

停止串流及所属服务后，验证完整替换组件和其前端资源，保留外部数据与旧包。没有通用 Windows 原位升级或数据库自动降级承诺；不能将一次手工维护描述成安装器自动升级能力。
