Source-built unified runtime installer candidates for Windows x64 and Ubuntu 24.04 amd64. Each platform's single installer contains the control service, management Web UI, Sunshine and Web/PWA media gateway. Audio/video examples, UE SDK probes, Playwright, acceptance scripts and test configurations are excluded. Node.js/npm and compiler toolchains are build dependencies only; they are not required on deployment hosts.

Run the downloaded setup EXE with `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART` for silent installation. Windows UAC still applies. See the source archive's `deploy/windows/README.md` for credentials, listener configuration, data retention and deployment boundaries.

On Ubuntu, use `sudo bash INSTALLER.run --user RENDER_USER`; add `--no-start` for installation without a desktop session. Native runtime libraries are resolved through apt. The selected user owns the rendering/audio session and private application data. See `deploy/linux/README.md` for startup and removal.

The workflow builds each platform's components and installer from the same clean source revision, verifies component inventories and publishes SHA-256 plus the source SBOM. Linux additionally extracts the actual package and executes three-component initialization without opening media streams. This proves source construction and package integrity; it does not perform host installation, physical microphone, UE5, native audio-device, GPU or production deployment acceptance. MSYS2 package versions are retained in the build logs; byte-for-byte reproducibility across changing distribution repositories is not claimed.

This is a prerelease. Windows product builds include the pinned open-source virtual-audio controller and the committed shared Audio class identity; driver files and identity are recorded in the installer manifest. Select the generated recording input in the target application. Physical microphone and unified-installation acceptance remain separate from package construction. Publisher signing is excluded from the current delivery scope.

For publication, the `windows-product-release` workflow requires both `promote_run_id` (the successful product build) and `installer_acceptance_run_id` (the successful `windows-installer-acceptance` run), plus the matching `release_tag`. Installer acceptance runs automatically after a successful product build. Promotion checks the acceptance artifact against the exact Windows installer source and SHA-256, including automatic SCM startup, native audio, component/service restart and uninstall. A successful build alone cannot authorize publication. This installation check does not establish a full machine reboot or physical microphone acceptance.
