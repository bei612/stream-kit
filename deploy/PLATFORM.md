# Stream-Kit 平台运行文件

本包包含同一源码提交构建的统一管理服务、管理页面、Sunshine 渲染端与 Web/PWA 媒体网关。产品版本、发布通道和完整文件摘要见 `platform-manifest.json`；组件清单保留各自源码版本和许可证。

每个平台使用一个安装包。Windows 可使用 `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART` 静默安装，系统 UAC 确认仍适用。Ubuntu 24.04 使用 `sudo bash INSTALLER.run --user RENDER_USER`；部署时需有可用的图形与音频会话。运行不需要安装 Node.js/npm、Go、Rust、CMake、UE SDK 或测试工具。

统一安装器初始化外部数据目录、唯一管理员和受管组件。Windows 安装器建立一个自动 LocalSystem 服务 `StreamKitOrchestrator`，由它管理 Sunshine 和网关；图形采集等待配置用户的交互桌面。Linux 安装器启用指定渲染用户的 `stream-kit.service`，`--no-start` 仅延后本次启动，不取消登录自动启动。不要重复注册独立 Sunshine 服务或另补启动项。

新安装默认管理入口为 `http://127.0.0.1:9000`；已配置 TLS 时使用 HTTPS，自定义端口以配置为准。其他设备使用服务器可达 LAN 地址或主机名，不能使用服务器的 127.0.0.1。管理员凭据位于数据目录受保护的 `orchestrator.json` 中，不应公开配置文件。

在管理页上传应用压缩包或选择本机已有程序，设置程序窗口或桌面采集，在启动前即可启用并复制固定观看链接。客户端通过该入口自动启动或加入应用；单个渲染主机当前同时一个应用串流，多个客户端共享，唯一控制权由管理员分配。通用程序录音需要实际可用的虚拟音频端点对，并在目标程序中选择对应录音设备；驱动是否内置以安装包清单 `audio_driver` 为准。不要把裸网关 URL 当作永久观看入口。

远程浏览器麦克风需通过可信 HTTPS 访问并由客户端允许录音。网络、证书、端口和音频端点按部署环境配置；重启生效的设置在管理页明确标注。变更前保留外部数据备份，升级时停止活动会话并保留旧版本。安装器不自动重启电脑、不执行数据库降级。

服务器换 IP 时更新原 CA 下 `server.lan_tls.hosts` 及相关显式公开地址/ICE 配置，预检后重启服务；保留 CA、服务私钥和观看密钥，不需重新编译或重装客户端信任。旧数字 IP 书签需修改地址部分，不会自行改写。停止应用后再改启动参数，关闭某个客户端不等于停止共享应用。

Windows 首次创建虚拟音频设备时，系统可能短暂将其选为默认输出。统一服务会在启动媒体网关前准备该设备的输出策略；准备完成后，该虚拟输出不参与系统及通信默认输出的选择。后续启动复用已完成的配置，不重复安装驱动。向目标程序投递麦克风仍需在管理页明确选择音频端点，并在目标程序中选择对应录音输入；安装过程不会替目标程序更改录音设置。

Windows 产品构建默认集成开源虚拟音频控制器，采用 Objective Development 公开的 Audio 类共享标识与系统音频类驱动。设备序列号包含发布配置中的邮箱前缀及每次安装生成的随机后缀；这是共享标识，不代表独占 USB 编号或 USB-IF 认证。使用规则见 [共享标识说明](https://github.com/obdev/v-usb/blob/801242072fa035e1839e3571df0d9a18e9cec95c/usbdrv/USB-IDs-for-free.txt)。
