# 音频目标动态配置：状态模型与运行时约束

目标是让单管理员在统一管理页选择目标应用的音频端点，实时切换并明确看到期望配置与实际生效状态。复用现有会话、SQLite、签名快照和 WebSocket，不建立第二个配置服务或设备账户体系。

本文区分已实现的数据基础与尚未实现的运行时，不能作为设备切换或目标程序实录的通过证据。

## 已实现：持久化目标状态

`session.AudioConfig.Target` 存入现有会话 `audio_json`，不新增表或独立配置文件：

```json
{"epoch":12,"mode":"local","render_device_id":"wasapi:output-id","capture_device_id":"wasapi:input-id"}
```

- `disabled`：不向目标程序上行；客户端广播由已有广播策略独立控制。
- `upstream`：使用上游声明支持的原生麦克风协议。不支持时不能伪装成目标已接收。
- `local`：明确选择本机输出与采集两端。必须为专用虚拟音频设备的配对端点，不按名称猜测、不回退系统默认设备。
- `epoch`：独立目标配置代次，采用提交版本。更新携带期望代次；旧页面、并发修改和 A→B→A 后的旧操作均拒绝。重选相同配置代表显式重试，产生新代次。心跳、控制权变化和增益/禁麦更新不改动目标代次。
- 本机端点在未停止会话之间独占，包含输出/采集交叉重复。停止中仍保留占用，已停止会话若恢复时端点已被占用则拒绝恢复。未来网关还必须保证实际资源销毁完成前不让另一个会话打开相同端点，数据库期望占用不能替代设备运行时所有权。
- 校验、持久化与内存发布使用现有单一会话提交边界；数据库失败不改变配置、不发成功事件、不唤醒发布器。
- 恢复时先校验所有已存端点占用。缺少目标字段的旧记录按 `upstream` 初始化，代次取现有版本，首次后续提交落盘；显式空对象、空值、非法模式/代次及重复占用不按旧记录降级处理。
- 普通观看连接收到显式音频策略投影，不包含本机端点标识。设备目录和完整配置仅供管理员使用。

当前 **没有开放目标修改 HTTP 接口或管理页选择表单**。领域命令已有数据测试，但现行 v2 媒体发布仍明确投影原来的五个音频字段，不能向旧网关偷偷增加其可能忽略的路由字段。若内部命令或后续数据库已包含非默认目标，v2 发布明确失败、停止确认新版本和发放新票据，绝不能把未发送的路由算作已生效。现有静态网关路由与媒体行为保持原协议含义。

## 待实现：协调升级协议与网关运行时

1. 将媒体状态升级为 v3，路由配置/代次为必填，并使用新端点、签名域及跨语言 fixture。网关拒绝缺失/倒退代次、同代次配置变化、重复端点。运行观测升级并携带对应目标代次，区分待切换、打开、失败、停用、上游传输及闲置；确认快照提交不等同于设备切换完成。
2. 管理会话由控制面目标配置作为唯一权威。旧静态配置仅保留给非受管理模式；受管理模式的遗留绑定必须显式迁移/核对，不能产生两套互相覆盖的来源。默认旧数据迁移不推断任意物理设备。
3. 网关在媒体时钟路径收到新代次后立即停止向旧端点写入并清空排队 PCM。原生关闭/打开在有界阻塞任务中执行，不持有媒体授权锁、不阻塞视频和广播。一次会话最多一个在途设备操作；最新期望状态合并，旧操作完成不能覆盖新代次。
4. 原生资源与端点占用由同一个生命周期对象独占；关闭完成后才释放占用。取消、最后一个观看者离开、控制租约失效、启动失败和快速重新连接都必须保持该顺序。旧监控句柄不能延长设备寿命。
5. 本机目标仅允许明确的同节点回环渲染主机；远端主机不能写到网关本机设备。无效/缺失/方向错误端点和设备失效都返回可见的实际失败状态，禁止自动改写默认设备或降级到其他目标。
6. 管理页选择来自实时设备目录；服务端再次校验选择与方向，使用期望代次提交。禁用、重试和切换只更新目标配置，保留增益、广播策略、控制权和观看连接。显示“配置已保存”与“设备已生效”的区别。
