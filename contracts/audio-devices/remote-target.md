# 跨节点麦克风目标：集成约束

本文件描述尚未实现的跨节点目标；现有 `local` 目标仍只作用于与渲染主机同节点的网关。不得将本设计视为已交付或将远端设备显示为已打开。

## 所有权

每个渲染节点运行本项目的网关进程，在 Sunshine 所在的音频用户上下文中持有原生端点。单一控制面维护节点身份、节点受信地址、会话与目标设备绑定，并向涉及该会话的媒体网关和渲染节点发布同一权威会话快照。浏览器只连接现有媒体网关；它既不选择节点地址，也不能获得节点间凭据。无需新账户体系或单独管理页面。

设备标识的作用域是节点，而不是全局字符串。目标应同时绑定节点身份、渲染主机身份、输入/输出端点对和目标 epoch；端点唯一性和占用在目标节点执行。控制面不得用媒体网关所在机器的设备目录校验远端设备。设备枚举必须返回节点身份及新鲜度；保存前重新校验，离线或无法认证的节点不能被当作空设备列表或成功配置。

## 音频与授权

媒体网关继续唯一持有浏览器音频解码和观众混音。只将已通过当前控制权和麦克风策略检查的音频送往目标节点；目标节点不重复混入程序声音。目标节点使用明确选择的输出端点写入虚拟设备，由目标程序选择对应输入端点，禁止回退系统默认设备。

节点间流必须通过 TLS 认证对端并使用域隔离、短期有效、绑定会话/节点/目标 epoch/控制代次的单次建连凭据。目标节点同时检查本地已验证且未过期的权威快照，不接受发送方仅凭自身声明授权。节点身份、会话、控制权、设备目标或媒体成员变化时，旧连接与缓冲立即失效；控制面续租失败、节点断线和连接关闭均清空待播放音频并关闭设备。目标节点应限制会话数、队列、单帧长度和重连频率，拒绝重放和旧代次。观众广播与目标写入故障相互独立。

音频数据以固定时间基准、有序帧和有限生存期传输；发送前、接收后和设备写入前均检查新鲜度，不能在网络恢复时播放积压语音。不得以节点连接存活、设备打开或写入帧数宣称目标程序已录音。

## 必须闭合的实施和验收

### 已实现的帧编解码基础（尚未接入网络）

`components/audio-target/src/wire.rs` 提供 Windows/Linux 共用的 `SKM1` 帧编解码器，未新增监听端口或远端设备选项。每帧固定 7716 字节：4 字节 magic、4 个 little-endian uint64（目标 epoch、控制代次、递增序号、原始音频接收时间 Unix 毫秒），随后为 1920 个 little-endian float32，即 48kHz 双声道交错 20ms PCM。不得在网络重试时重写音频时间。序号从 1 开始，允许丢帧但拒绝重复与乱序；新认证连接须创建新的接收状态。

解码检查帧长度、版本、非零代次、目标/控制代次匹配、时间新鲜度及所有样本有限性。接收时间不得早于帧时间，帧年龄必须小于原生输出队列共用的 60ms 上限；两节点时钟须先同步。格式失败不推进序号，也不修改输出缓冲。编解码过程使用固定缓冲，不按输入声明分配内存。此处的时间约束只是传输契约，尚无时钟偏差准入实现。

原生目标现提供 `AudioTarget::submit_captured(samples, captured_instant)`：将原始接收/采集时间带入同一输出队列，在入队前拒绝过期及未来时间戳，设备回调仍按原始时间过期，不能重新获得 60ms。现有本机 `submit` 通过该接口提交，保持本机处理行为。协议→队列联合测试验证 50ms 网络耗时加 5ms 处理耗时后仅剩 5ms，以及无效旧帧不驱逐队列内有效音频。

后续网络接收端必须在解码之外验证 TLS、单次票据、实时会话快照和节点/会话归属；在解码前记录本机 monotonic 接收时刻，减去解码返回的原始年龄后传给 `submit_captured`，使解码和调度耗时同样计入期限。当前模块没有替代这些授权检查，也没有连接网络或证明跨节点送音成功。

扩展现有节点配置、会话快照及版本化签名 fixture；实现节点注册、目标节点设备目录、短期票据及接收端独占生命周期；接入同一管理页面的节点选择、目标配置、实际设备状态和错误；在断线重连、撤权、换人、禁麦、切换设备与服务重启时验证旧音频不泄漏。Windows 和 Linux 使用相同协议与目标抽象，平台设备由原生后端负责。

完成前至少需在两个独立进程和不同监听地址验证发送、认证失败、过期票据、旧 epoch、连接中断和设备资源回收；再使用专用虚拟输入实际录下浏览器测试音，并同时验证所有观众听到混音。合成目标或模拟设备只能验证协议，不能替代真实目标录音。Linux 和移动端本轮无需真机验收，但 Linux 源码与构建不得省略。
