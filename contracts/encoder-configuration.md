# 编码器期望配置事务

本协议适用于本项目编译的 Sunshine 原生配置 API。统一管理页已接入显式参数编辑、启动文件版本证据和受管重启加载确认；完整参数目录与参数有效性校验仍需接入，此处不代表全量参数管理已经交付。

## 读取和保存

`GET /api/config` 经现有管理员认证后返回期望配置，保持既有平面 JSON 字段，并在响应头返回强 `ETag`。指纹由完整文件字节计算，包含注释和格式变化；响应禁止缓存。文件不存在表示默认配置，无法读取、非普通文件或超过 1MiB 则返回 500，不返回可写的空配置或版本。

`POST /api/config` 保持完整替换语义，提交 JSON 对象和 `If-Match: <读取所得 ETag>`。既有认证、CSRF/来源校验继续有效。缺失或重复 If-Match 返回 428；版本不匹配返回 412，不更改文件，也不自动合并或重试。客户端需重新读取并审阅差异后再提交。通配符和多版本列表不支持；必须匹配读取所得单一强指纹。

版本匹配后执行同目录原子替换。成功返回 `status: true`、`apply_policy: encoder_restart` 及新 ETag。页面保存成功后更新本地指纹，下次保存携带新指纹；读取失败或确认缺失时不能默认为成功。空对象仍表示清空显式配置，必须提交当前版本。

保存失败返回 500。`committed: false` 表示没有提交替换；`committed: true` 表示替换已经发生但持久化未完全确认，客户端必须重新读取，不能盲目重试。保存不修改当前运行配置，成功保存不是重启完成或参数已生效的证据。

## 并发与边界

原生 API 的读取、比较和提交，以及自动补写缺失配置选项，共用进程内事务锁。自动补写也采用原子替换，不原地截断配置；任何成功写入都使与新字节不匹配的旧指纹失效。锁只序列化本进程的这些写入者，不锁定外部文本编辑器，也不提供跨进程文件事务。外部编辑在下一次读取/提交校验时反映为新指纹；不保证校验与替换之间外部进程并发写入的互斥。

请求限制 1MiB、最多 512 字段；字段名最多 128 字节，仅允许 ASCII 字母、数字和下划线。值拒绝 NUL；包含换行或回车时，仅允许原生解析器完整识别为同一字段、同一值的多行列表，拒绝尾随配置行、注释或第二个列表。这样读取已有多行命令配置后，修改其他字段不会因合法列表换行而失败。null 和空字符串沿用省略行为。参数类型、范围、平台能力的统一目录和运行版本确认尚未完整实现，不应把结构验证视为完整配置校验。

旧客户端没有 If-Match 将收到 428，必须随本项目源码一并升级，不提供无版本覆盖通道。

## 统一控制面适配

`GET /api/v1/encoder-configuration` 和 `PATCH /api/v1/encoder-configuration` 使用 Orchestrator 现有管理员 JWT 鉴权，响应禁止缓存。GET 返回 `revision`、`values`、`redacted_keys`、`apply_policy: encoder_restart` 和 `runtime_verified: false`。当前返回显式配置，不包含尚未建立的完整默认参数目录。

仅已分类的显示、采集、编码、音频和输入基础字段返回原值；命令、密钥相关字段及未分类扩展均返回 null，并列入 `redacted_keys`。这不代表原值为空。保存时应省略未修改字段，不可把脱敏 null 自动回传；显式提交 null 表示删除该覆盖项，恢复原生默认值。字段分类将随参数目录完善扩充。

PATCH 请求为 `{"revision":"<原生强 ETag>","changes":{"sunshine_name":"Renderer"}}`，字段键使用原生配置名，最多 256 项，请求最多 256KiB。客户端读取当前原生配置并核对版本，合并修改后再以同一 If-Match 提交；读取期间和提交期间发生的并发修改均拒绝覆盖。未修改的敏感值保留在服务端，不经过浏览器。

成功仅返回本次提交的 `revision`、`apply_policy` 和 `runtime_verified: false`，不将后续读取的其他事务版本冒充本次结果。冲突返回 409，结构无效返回 400，无法读取或确认写入返回 503；错误响应不包含原生正文或配置值。不自动重试写入。保存与受管重启是分别执行的操作。

## 启动文件证据

原生 `GET /api/stream-kit/configuration-state` 复用管理员认证，返回协议 `schema_version: 1`、当前文件 `revision`、`runtime_available` 和 `apply_policy: encoder_restart`。成功启动后额外返回 `loaded_revision`、随机 64 位十六进制 `instance_id`、命令行覆盖字段名数组 `overridden_keys` 以及 `restart_required`（当前文件版本是否不同于启动读取版本）。没有启动证据时不返回 `restart_required`，不能将未知解释为已生效。

启动过程使用与配置 API 相同的有界二进制文件读取，哈希基于实际送入解析器的字节。只有运行配置应用完成后才发布启动证据；API 保存和自动补写不会改写它。覆盖只返回字段名，不返回值。版本相同证明进程启动时读取了该文件，不证明所有参数被接受、没有命令行覆盖或平台实际支持；因此统一接口仍不声称 `runtime_verified: true`。

统一控制面读取参数后读取启动证据，两次读取的期望配置版本必须相同，否则返回冲突而不拼接不同版本。管理页展示启动版本、待重启状态及命令行覆盖；保存成功后立即将本地显示更新为待加载的新版本，继续编辑仍要求重新读取。

## 受管重启加载

原生启动状态还返回 `process_id`；由组件管理器启动时返回其通过 `STREAM_KIT_PROCESS_INSTANCE` 注入的 32 字符小写十六进制 `managed_instance_id`。该管理标识与每次启动生成的 64 字符 `instance_id` 分开校验。未受管实例不显示统一页面的重启应用按钮。

`POST /api/v1/encoder-configuration/apply` 使用管理员鉴权，请求为 `revision` 与当前启动 `instance_id`。仅支持明确的回环 IP 地址，拒绝远端和 DNS 主机名。操作复用组件管理器 `RestartVerified` 生命周期锁：核对受管 PID 和管理实例标识，在停止前重新检查启动实例及期望配置；启动替换进程后核对新 PID、新管理实例、新启动实例、目标文件加载版本及待重启状态。旧页面重复提交返回冲突，不重启新实例。失败不自动回滚；监听地址、证书或凭据变更导致无法连接时返回未确认。

页面要求先保存或撤销草稿并重新读取，提示重启会中断渲染和观看连接。成功表示新实例加载了目标文件，仍不证明全部参数已被原生解析器接受或命令行覆盖不存在。
