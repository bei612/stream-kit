# 管理前端状态与数据一致性

本文定义管理前端的长期状态管理原则及现有实现。部署版本和实际页面检查见[发布与部署基线](release-status.md)，不在本文件追加逐次排错过程。

## 单一权威来源

会话、连接、控制权与音频策略由服务器管理。客户端缓存只投影服务器，不拥有权限，不从按钮状态、旧票据 role 或某次保存结果推断当前控制权。

| 状态 | 所有者 | 前端处理 |
| --- | --- | --- |
| 应用/组件/日志/健康 | 对应管理 API | 资源查询缓存及明确加载/错误状态 |
| 会话 + 网关确认 + 运行观测 | overview 同一服务器快照 | 同时核对身份、revision 和新鲜度 |
| 配置编辑 | 本地草稿 + 服务器 revision | 原值、草稿、保存中、冲突及待重启分开 |
| 固定观看链接 | 应用记录 / 管理操作 | 初次读取完成前不能修改；不确定变更结果需重新权威读取 |
| 登录与缓存生命周期 | 管理登录身份 | 失效、切换凭据、退出清理缓存和事件连接 |
| 播放尝试 | 当前 watch 操作 | 每次尝试拥有 iframe/请求，替代后释放旧资源 |

## 查询缓存

使用项目锁定的 TanStack Query；集中键位于 `orchestrator/web/src/api/query-client.ts`，查询封装位于 `hooks/useQuery.ts`。应用 ID、日志页码和筛选进入资源键，不同资源不共享一份散落的 data/loading/error。

查询不额外自动重试，未订阅后立即回收，不把服务器结果持久写入浏览器存储。普通 API 透传查询的 AbortSignal 并保留请求超时。WebSocket 事件触发查询失效，既有轮询提供补偿；不能以事件到达替代获取当前权威快照。

日志行与 total 来自同一次响应，翻页按服务器 total。上传和普通请求使用同一响应外层及登录失效处理；创建应用只有取得实际 ID 才跳转，不使用固定延时或伪造 ID。

显式刷新须确认当前查询身份、启用和挂载状态。失败、取消或已被替代的结果不算完成，不能把旧缓存显示成命令已经生效。客户端取消和网络故障分别诊断，不能吞掉失败。

## 会话 overview

管理页读取 `GET /api/v1/stream-sessions/overview`。服务器在发布器同步边界获取：

- `sampled_at` 服务器采样时间；
- `sessions` 会话快照；
- `media` 网关可达性、已确认版本及实际观测。

旧 `/stream-sessions` 和 `/media-control` 保留兼容，管理页不再拼接两套独立轮询缓存。未配置网关仍返回真实会话，但媒体状态为不可用。

显示有效运行必须同时满足会话/实例身份、revision、控制代次、网关租约及新鲜观测。配置保存但未确认、正在启动或合法版本差异均显示等待同步；不能删除版本判断使页面“更绿”。

## 时间和迟到响应

时效计算以服务器 sampled_at 为基准，保守计入请求耗时，再使用客户端墙钟与单调时钟的较大经过时间老化。客户端固定时钟偏差不改变服务器租约；回拨不能延长权限，前跳保守失效。定时重绘只触发刷新显示，计算读取当前时间。

命令、参数草稿、候选入口、链接变更及播放器尝试具有各自归属。请求结果只可写入仍匹配的应用、配置 revision 和操作代次；组件卸载或替代操作后取消/丢弃旧结果。剪贴板完成回调也不能回写已替代链接。

## 编辑与实际生效

`useConfigurationDraft` 维护草稿及冲突边界；应用命令和页面挂载按应用身份隔离。脱敏字段保持“不变”语义，不能把脱敏占位值作为真实秘密写回。

管理服务 `Settings` 保存文件期望值，启动时运行配置保持不变；页面显示待服务重启。网关/编码器应用操作由服务端重启对应组件并验证运行实例和 revision。保存成功、应用成功和真实媒体恢复分别表示，不能用同一 toast 代替三个事实。

停止历史会话只读，不显示控制权、音频或策略修改操作。在线连接、历史运行和当前应用记录分组呈现，离线记录不计入在线人数。

## 维护与验收

修改状态管理前须同时核对 API 返回、全部消费者、缓存键、登录清理、时钟、命令/刷新与失败路径。前后端资源必须与接口版本配套；回退到不支持 overview 的后端时同步回退前端。

真实部署验收覆盖刷新、分页、保存后读取、停止后编辑、控制交接、明确终态及移动布局；使用 playwright-cli 并检查截图、控制台和网络。原库异步测试及源码检查补充竞态验证，不替代真实页面，也不向生产加入探针。
