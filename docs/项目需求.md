# Stream Kit 产品需求

本文定义当前产品的功能边界。实现原理见[技术架构](技术架构细节.md)，操作步骤见[使用手册](user-guide.md)，实际发布及验收状态见[发布与部署基线](release-status.md)。需求成立不代表所有环境已经验收。

## 产品定位

平台管理服务器上的可执行程序，将程序画面和声音分发给浏览器或 Android 客户端，并允许管理员把唯一操作权及麦克风发送权交给某个在线连接。UE5 是可运行的目标程序之一，不是平台唯一支持的程序类型。数字人 API、DataWind 业务和场景制作不属于串流平台本身。

服务端为 Windows 或 Linux；客户端为桌面浏览器、移动浏览器/PWA 和原生 Android。iPhone/iPad 使用浏览器，不包含原生 iOS App。仅一个平台管理员，观看连接不是用户账户，不新增注册、组织、角色管理系统。

## 应用管理

| 能力 | 要求及当前行为 |
| --- | --- |
| 本机程序 | 输入服务器本机绝对路径、工作目录及参数；路径属于服务器，不是客户端文件路径 |
| 压缩包 | ZIP、7z、RAR、TAR 及 gzip/bzip2/xz/zstd 压缩 TAR；控制服务内部解码，不要求服务器安装 7z/WinRAR |
| 不支持的归档 | 加密、分卷、链接及特殊文件明确拒绝；损坏、越界、重复路径和资源超限不能报告成功 |
| 入口选择 | 检测候选并选择真实可执行入口；Linux 本机文件须已具有执行权限 |
| 启动配置 | 名称、入口、工作目录、参数、模板和采集范围统一管理；模板解析和实际执行使用同一参数规则 |
| 修改生效 | 先停止应用及串流，确认原生实例结束，再保存启动配置；下次启动使用新配置 |
| 删除语义 | 上传应用清理平台拥有的文件；本机程序登记仅移除平台记录和所属目录，保留外部程序 |
| 故障处理 | 解包、登记、配对、启动失败保留真实错误，支持按当前状态重试，不用固定等待后跳转假装成功 |

参数来自管理员保存的配置。公共观看链接不能自行指定其他程序或用 URL 查询参数覆盖命令行。应用返回的普通 JSON 不包含固定观看密钥。

## 串流及并发

同一应用的多个观看端共享一个上游渲染串流，各客户端拥有独立连接、解码和播放设置。一个观看者离开不能关闭其他观看者的媒体。

**当前单渲染主机同时只支持一个应用串流。** 三个应用可以登记和轮流运行，不能据此让三套独立应用并行串流。多节点接口或音频路由配置不代表已经交付跨节点应用调度、GPU 隔离或并发桌面。

| 采集模式 | 语义与限制 |
| --- | --- |
| 桌面 | 明确采集服务器桌面；管理员承担桌面其他内容可见的影响 |
| 指定程序 | 绑定实际程序执行身份、窗口/表面及程序音频；不能找不到目标后退回桌面 |
| Windows 输入 | 程序模式核对目标窗口及焦点；系统级输入不是沙箱隔离，不能承诺阻断所有系统快捷键或其他 Raw Input 接收者 |
| 平台能力 | 按当前编码器能力开放配置，不支持的模式应明确拒绝；不能把某平台后端存在等同所有桌面/驱动均可用 |

码率、帧率、分辨率与编码支持受 GPU、驱动、客户端解码能力及共享上游协商约束。20 客户端已有稳定性证据不等于任意硬件的容量保证。

## 固定观看入口

应用详情在点击启动前即可启用并复制 `/watch#key=…` 链接。链接长期有效，打开时自动按后台保存参数启动程序，已运行则加入现有串流。网页保留固定入口，内部短时邀请和媒体票据按需换取。

管理员可轮换、禁用链接或删除应用。轮换阻止旧链接再次入场，但不自动踢出已经建立的连接；需要立即收回观看时应断开连接或停止应用。

链接是持有即准入的能力凭据，应只交给允许观看的人。客户端不需要管理员密码。数字 IP 地址变化需要更新链接的地址部分；保持观看密钥不等于旧 IP 自动可达。

## 会话、连接与唯一控制权

- 应用记录长期存在；渲染会话描述一次受管运行代次；连接描述某个客户端当前加入，不是设备永久档案。
- A/B/C 一周后重新打开固定链接，通常建立新连接；不能把历史连接作为永久账户延续。
- 客户端默认为观众。管理员在当前在线连接中授予、转交或释放唯一控制权，客户端明确显示身份。
- 同一时刻只有一个有效控制者可发送输入和麦克风。旁观者、旧控制代次、失联及过期连接被服务端拒绝。
- 活跃连接租约 15 秒，客户端每 5 秒续租；可恢复记录仅用于有限时间恢复同一连接，恢复后以观众身份进入，不自动恢复麦克风。
- 明确终止后关闭媒体与录音并停止自动恢复。再次进入由用户主动打开有效观看入口。
- 已停止会话仅作只读历史，按当前策略保留最多 100 条、最多 7 天；不是在线人数，也不允许编辑其控制权、声音和策略。

## 音频

程序音通过渲染端采集到网关；唯一控制者麦克风由客户端主动采集，经网关送到管理员指定服务器录音端点，同时按会话设置与程序音混合广播给观看者。

| 项目 | 要求 |
| --- | --- |
| 客户端采集 | Web 需安全上下文和录音授权；Android 需系统录音授权；获得控制权不自动开始采集 |
| 服务器接收 | 目标程序选择实际录音端点；网页授权成功或收到 RTP 不等于目标程序已录到 |
| Windows | 使用集成的开源虚拟音频实现及已签名控制器驱动；不依赖 VB-CABLE，也不是虚拟显示驱动提供录音 |
| Linux | 使用渲染用户的 PulseAudio/PipeWire-Pulse 专用虚拟端点；不新增独立音频守护进程 |
| 路由 | 明确选定输出/录音端点，不缺省回退到系统设备；不同目标的设备所有权不能冲突 |
| 生命周期 | 撤权、租约失效、后台和权限拒绝时释放输入及采集；租约恢复后需重新授权并主动开麦；Web 同身份同控制代次的短时媒体修复另按连接契约处理 |
| 体验 | 程序音量、麦克风音量、广播和控制者监听按管理策略生效，避免把客户端回声当成服务器新声源 |

生产安装不包含测试音源、录音探针或 Example。虚拟录音是实现通用目标程序接收远端声音的运行能力，不等于将测试工具装给客户。

## 管理配置与界面

应用、组件、观看会话、配置及日志使用统一管理入口。前端以服务器结果为准，数据、加载、错误和分页归属于同一请求；晚到结果不能覆盖其他应用或更新的操作。状态快照同时关联会话、网关确认及原生运行观测，不能用“保存成功”冒充“正在串流”。

| 配置 | 生效方式 |
| --- | --- |
| 控制权、会话音量、广播和策略 | 当前会话更新并等待网关确认 |
| 客户端解码/媒体协商参数 | 按客户端设置提示重新连接 |
| 应用参数、入口及采集模式 | 停止应用后保存，下次启动 |
| 编码器 / 网关原生配置 | 保存期望值后应用对应组件；核对运行版本和实例 |
| 管理服务监听、凭据和 LAN TLS | 保存后重启管理服务；必要时重新登录 |

受支持参数以当前管理页面和原生配置目录为准；不承诺可编辑所有上游未纳入的实验参数。只读脱敏配置不能代替可编辑表单，脱敏值也不能作为新密码写回。

## 部署和安全

Windows/Linux 各一个统一安装器，静默优先，安装器建立服务启用与恢复关系。Windows 一个 SCM 服务管理 Sunshine 和网关；Linux 为指定渲染用户的 systemd 用户服务。桌面/音频会话不可用时，不能仅凭控制端在线宣称渲染就绪。

新安装默认本机 HTTP。LAN 使用需配置监听、防火墙、HTTPS、客户端信任及媒体 UDP。只有 IP 也能部署，不要求购买域名。IP 变化时更新原 CA 下的 TLS 身份、显式公开地址和必要网络配置，重启归属服务；不重新编译、不重装客户端 CA，不忽略 TLS 错误。

凭据按管理员、永久观看、短时邀请、连接、媒体票据及节点签名目的隔离。生产包不含私钥、测试账号、示例、临时数据库和构建工具。安装器不自动重启电脑，不提供未验证的 Windows 原位升级或数据库自动降级。

## 交付与验收

交付安装器、签名 APK、源码/文件清单、SHA-256、许可证及长期操作文档。产品发布、本机组件维护和真实页面验收分别证明。

浏览器验收使用实际部署页面的 playwright-cli 操作及截图；音频须区分程序播放、客户端采集、服务器端点录音和观看端广播。既有四小时/20 客户端与真人语音证据按其版本保留，不要求反复测试。本轮不要求 Linux 或手机真机验收；Android 模拟器结果不等于真机性能。剩余验收见[基线](release-status.md#尚未闭合的生产验收)。
