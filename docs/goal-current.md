一、交付范围
1. 保留跨平台 Web/PWA 客户端，覆盖 Windows、Linux、Android 手机/平板及 iPhone/iPad 浏览器；新增基于官方 moonlight-stream/moonlight-android 源码二开的 Android 原生 App，交付可安装、可持续升级的 release APK。不得用 WebView 套壳或原版 Moonlight APK 冒充统一集成。iOS 原生 App 不在本次新增范围。
2. 服务端支持原生 Windows 和 Linux；Orchestrator、Sunshine、媒体网关共用统一管理后台、应用模型、会话协议和运行生命周期。只有一个管理员，不引入多用户账户体系或重型监控等非核心功能。
3. Sunshine、Moonlight Web、Moonlight Qt、Android 及必要依赖在同一仓库纳管，禁止 submodule；锁定可追溯上游提交，保留许可证与二开记录。官方 Android 原生解码、渲染、输入和设备能力应合理复用，先梳理协议差异再实施，不能拼接互不受控的独立系统。

二、核心功能与一体化约束
4. 同一 host/app 共享一个上游渲染会话；Android 和 Web 加入同一受管理会话，共享程序画面与声音，不能让 Android 私自直连 Sunshine 绕过授权或创建第二条上游。管理端统一显示各客户端类型、连接状态、唯一控制者，实时移交/撤销控制权。
5. 唯一控制者的麦克风送达指定服务器录音端点/目标程序，同时与程序音混合广播给各观看端；Android 与 Web 均遵循服务端权限和控制代次约束。禁止旁观者、旧控制者、断线或过期连接发送有效输入/麦克风。覆盖设备权限拒绝、音频焦点、前后台切换、重连和资源释放；不后台偷偷录音。
6. 永久应用链接在启动前可见，打开即可按后台保存的参数唤起应用并开始串流；链接可主动轮换使旧链接失效。Android 支持接收/导入该链接，凭据安全保存且不进入日志。永久入口与短时媒体票据分层，不能把观看入口限制为两分钟。
7. 服务监听、信令、ICE 与媒体地址不能向远端泄露不可用的 loopback 地址；支持只有局域网 IP 的部署、地址变化后的重新发现/重连并保持服务身份。明确旧数字 IP 书签不会自动改写；采用经过核查的发现/地址更新方案，不虚称任意 IP 变化无影响。TLS 正确验证证书，不以忽略证书错误实现生产连接。
8. 应用支持指定本机程序路径或上传 ZIP/7z/RAR/TAR 及常用压缩格式；安全解压与外部路径所有权统一处理。桌面/指定程序画面及声音可配置，程序模式禁止回退泄露桌面或无关应用声音。
9. 全部受支持的可配置参数进入管理页，明确即时、重连或重启生效；期望配置与实际状态分离。统一管理端、Web 和 Android 的连接/启动/停止/失败/重试状态模型，处理并发、陈旧响应和幂等操作；采用专业、轻量、一致的界面，不增加无关功能。
10. Example 覆盖画面、输入、程序发声和麦克风接收，作为独立开发验收工具；生产安装包不得混入 Example、测试音源、探针、测试凭据或调试依赖。

三、安装、调试与发布
11. Windows/Linux 各提供一个统一服务端安装包，静默优先；安装程序本身建立全部必要服务的开机/登录启动与恢复关系，不依赖人工补启动项。运行不要求宿主机另装 Node.js，不依赖 VB-CABLE，不要求商业发行证书。
12. Android 使用官方 Android SDK/Emulator 与稳定工具链，在本机 Windows 安装和调试，优先可用硬件加速；先盘点已有 SDK、虚拟化和磁盘，复用已有工具，不引入第三方安卓游戏模拟器，不擅自重启或改动共享主机的系统虚拟化配置。使用可复用 AVD，限制镜像、缓存和磁盘增长；测试内容不进入正式 APK。
