# 局域网地址配置与信任保持

服务身份与 IP 地址分开维护。`server.lan_tls` 启用后，服务启动使用已有部署 CA 为配置中的 IP / 主机名签发服务证书；CA 证书及私钥保持不变，服务私钥继续复用。客户端初次信任该 CA 后，后续地址变更不需要重装 CA 或重新编译客户端。

## 服务端配置

管理页“服务配置 → 管理服务与登录 → 局域网 TLS 身份维护”对应以下字段：

```json
{
  "tls_cert": "tls/server.crt",
  "tls_key": "tls/server.key",
  "lan_tls": {
    "ca_cert": "tls/ca.crt",
    "ca_key": "tls/ca.key",
    "hosts": ["192.168.1.10", "render.local", "localhost", "127.0.0.1"]
  }
}
```

路径相对于管理服务配置文件目录；上例是 `server` 对象的部分字段。CA 使用部署时建立并已被客户端信任的那一份，不能填入另一份新 CA。私钥文件仅由服务账户和管理员访问，不随客户端或公开安装包分发。

管理服务和本机媒体网关必须使用相同的服务证书/私钥路径。管理服务在启动网关前更新证书。配置保存后重启服务生效；`check-config` 只做检查，不写入证书。地址不变、证书有效期超过 30 天时不会重复签发。临近过期的服务证书在下次启动时续签；CA 本身到期需要独立维护，不会静默替换客户端信任根。

服务器换 IP 时：

1. 将新 IP 加入 `server.lan_tls.hosts`，保留仍使用的本机健康检查地址。
2. 若管理服务或网关绑定了具体 IP，更新监听地址；使用通配监听时无需改动。若显式配置了浏览器访问地址、来源白名单、媒体公开地址或远程节点地址，也应更新相应配置。
3. 重启 Stream Kit 服务，使用新地址访问。数字 IP 书签不会自行改写；应用观看链接的密钥保持不变，只更新地址部分。

媒体网关仍按当前网络协商 ICE 地址；地址迁移会使原连接断开，需要重新连接。只更改浏览器页面 URL 而留下旧网关地址、显式 ICE 地址或防火墙配置，不等于完成迁移。

## 客户端配置

Android 断开连接后，在入口点击“修改服务器地址”，填写新的 HTTPS 地址和端口。此操作保留已保存的应用观看密钥，不必重新导入密钥；不会放宽 TLS 校验。Web 入口相应修改 URL 中的地址，保留 `/watch#key=…` 部分。

仅客户端自身换 IP 不改变服务器证书或观看密钥；网络切换后重新连接即可。服务端仍须能被新的客户端网络访问。

## 当前验证边界

源码测试覆盖同一客户端 CA 信任池验证地址更新后的真实 TLS 握手、CA 和服务私钥保持不变、拒绝静默更换签发 CA、只读预检、配置相对路径与无变化不重签；Android 协议检查覆盖地址更新保持观看密钥和拒绝不安全地址。该证据不是本机实际网卡 IP 切换验收。功能需要包含本次变更的新服务端与 Android 构建部署后生效，不能由既有安装版本推定已具备。

2026-11-10 本机控制端为 `571295af`、媒体网关 `40146db2`、Sunshine `47c02726`，已保持现有部署 CA 并完成真实 LAN HTTPS 页面验收，见[本机记录](evidence/management-overview-local-windows-571295af.json)。这证明当前地址访问，不等于宿主机实际主地址迁移或整机重启。

## 共享宿主机实际验收及回退

以下操作会影响同机其他项目，必须在已确认的维护窗口内执行；不通过改动 ToDesk、强制结束 UE 或绕过 TLS 获取验收结果。

1. 保存其他项目工作，核对当前没有外部观看者或运行中的非 Example 应用。记录主网卡、DHCP 状态、实际地址、网关、系统启动时间、组件源码版本和服务启动方式。对现有配置、证书路径及必要运行数据作小范围受保护备份；保留原 CA 和服务密钥，不另建信任体系。
2. 在允许网络中断后，通过实际部署网络的正常 DHCP/网络切换取得不同的可达主地址。不能猜测空闲地址并强行设置静态 IP，也不能用独立网卡增加别名替代主地址迁移。记录实际新旧地址；若 DHCP 仍分配原地址，只能记录“未发生地址变化”。
3. 从服务器本机受信入口更新新 IP 对应的 TLS 身份及所有显式公开地址、来源和 ICE 配置，沿用原 CA、服务密钥、应用 ID 与观看密钥。预检成功后只重启 Stream Kit 归属服务。若预检或恢复失败，停止验收并按备份回退配置，不继续叠加改动。
4. 从已有可信客户端更新地址部分进入同一个永久应用入口，使用独立 Example 检查应用自动唤起、真实视频解码和程序音、控制权操作以及数据面可达；确认没有旧 loopback/旧 IP 依赖。Android 可使用已有官方 Windows 模拟器，不要求物理手机或重新安装 CA。原数字 IP 书签失效是预期现象，不能把它算作自动改写。
5. 在另行确认可重启、其他项目已保存后手动重启整机。登录后先记录新的系统启动时间，检查安装器建立的服务与子组件自行恢复，再通过永久入口进入 Example。验收期间不得手工启动服务、补启动项或以已有服务状态代替新开机证据；需要人工补启动才恢复时应记录失败并修复安装/启动链。
6. 回退时恢复原网络接入与受保护的应用配置、证书路径，必要时重启归属服务。DHCP 可能分配不同地址，不能承诺原数字 IP 一定恢复；按实际地址更新原 CA 下的身份即可。保留失败记录和新旧配置，不能删除现有应用或重新生成观看密钥。验收结束后停止 Example、清理归属连接并恢复空闲。

证据应分别记录地址迁移与整机重启的实际时间、网络/启动前后值、部署版本、相同 CA 与密钥保持情况、真实客户端操作和数据面指标。配置预检、组件服务重启、独立 CI 网卡实验和运行中的 `Auto` 状态均不能替代上述两项实际结果。
