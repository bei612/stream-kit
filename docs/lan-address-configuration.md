# 局域网地址、HTTPS 与 IP 变更

本文同时覆盖管理端和媒体数据面。只有 IP 的局域网可以部署，不要求购买域名；IP 地址、名称解析、证书信任和媒体可达性需要分别配置。现场地址见[部署基线](release-status.md)，不要把文档中的示例当作实际主机地址。

## 本机、LAN 与协议

| 入口 | 应使用的地址 |
| --- | --- |
| 新安装、本机默认 | `http://127.0.0.1:9000` |
| 已启用 HTTPS、本机 | `https://127.0.0.1:9000/login`，证书须覆盖 loopback |
| 其他设备 | 可达的服务器 LAN IP 或可解析主机名，使用部署实际 scheme/port |
| 观看 | 应用详情的 `/watch#key=…` 永久入口，不是裸 `stream.html?hostId=…&appId=…` |

`127.0.0.1` 总是当前设备自身，不能交给其他电脑/手机访问服务器。已启用 HTTPS 的监听不继续服务 HTTP。远端浏览器录音须可信 HTTPS 和用户授权；localhost 的浏览器安全上下文特例不适用于普通 LAN IP。

## 两类地址分开

内部组件 API 保持本机 loopback，避免绑定 DHCP 地址。对浏览器公开的 URL 由管理页的实际 hostname 和网关端口派生；同机部署通常保持 `moonlight_web.public_url` 为空。

网关生成 `config.js` 时，将内部 loopback/unspecified 控制主机替换为客户端请求的 authority/Host，保留控制端 scheme/port/path；显式外部主机 override 不会被覆盖。CORS `https://{host}:8080` 只匹配当前管理主机、指定协议及端口，不是任意来源白名单。具体规则见[公开地址契约](../contracts/public-addresses.md)。

页面地址正确不能证明数据面正确。还需核对网关信令、ICE/NAT 映射、实际 UDP 范围、防火墙和返回候选，不能向远端返回无法使用的 loopback。

## 保持部署 CA 的 TLS 身份维护

启用 `server.lan_tls` 后，控制服务在启动监听器及网关前，用**已有部署 CA**签发包含配置 IP/主机名的服务证书。CA 和服务私钥保持不变。客户端初次信任该 CA 后，地址更新不需重装 CA 或重编译客户端。

以下是需替换为实际部署值的配置示例：

```json
{
  "tls_cert": "tls/server.crt",
  "tls_key": "tls/server.key",
  "lan_tls": {
    "ca_cert": "tls/ca.crt",
    "ca_key": "tls/ca.key",
    "hosts": ["192.168.1.10", "render.local", "localhost", "127.0.0.1"]
  }
}
```

这些是 `server` 对象中的字段。相对路径以控制端配置目录解析；四个文件路径必须不同。CA 与服务私钥保持受保护，不随安装器/APK或普通配置导出分发。

管理端与本机网关共用同一服务证书/私钥路径。地址未变且服务证书有效期超过 30 天时不重复签发，临近过期在下次启动续签；CA 失效不能通过静默换根处理。`check-config` 仅检查，不写入证书，也不代表客户端已信任。

初次由 HTTP 改为 HTTPS 时，必须一并更新管理监听 TLS、网关 TLS、控制/网关内部调用 URL、网关健康检查、CORS 和公开 URL，并建立服务账户及各客户端信任。只让浏览器信任 CA 不能证明后台系统信任已配置。

## 服务器换 IP：正常配置流程

当前实现不是自动追踪 DHCP 的证书管理器。地址变化后按以下顺序处理，不重装产品、不重编译、不另建 CA：

1. 在本机可信入口或管理员终端确认真实新 IP、当前监听、组件及应用状态。不要猜空闲 IP、改网卡别名或结束其他项目进程。
2. 通过后台正常停止活动应用，等待原生实例和会话终态；备份受保护配置及原证书，准备回退。
3. 在服务配置的“局域网 TLS 身份维护”给 `server.lan_tls.hosts` 加入新 IP，保留实际使用的本机健康检查地址及稳定主机名。
4. 核对具体 bind 地址、显式公开 URL、CORS literal、ICE/NAT 映射及防火墙接口。通配 bind、空 public_url、同主机模板及内部 loopback 无需为了换 IP 改成具体地址；远端节点只更新确实迁移的节点。
5. 执行原生控制端及网关配置预检。保存期望值并不使当前监听自动重载。
6. 只重启 Stream Kit；原 CA 和原服务私钥下生成新证书，两个入口采用一致身份。核对控制端及自动组件就绪。
7. 在已信任客户端用新地址打开管理页，再打开同一应用的永久入口。检查实际视频、程序音、目标输入、麦克风到录音端点及观看端；TLS、页面与数据面分别确认。
8. 成功后保持应用/密钥，按需恢复运行；失败先停归属服务并恢复备份配置/证书，不叠加忽略 TLS 或新 CA 的绕过。

Windows 受保护配置和 SCM 重启需要管理员权限/UAC；这不是重新安装。恢复旧配置只能恢复旧地址身份，网络若已改变仍需按真实地址维护，不能承诺旧 IP 一定可达。

## 书签和 Android 地址

数字 IP 书签不会自动改写。把 `https://OLD_IP:9000/watch#key=…` 的地址部分改为新地址，保留同一 key；新地址也必须在证书 SAN 中。固定链接长期有效指应用准入密钥的生命周期，不是数字 IP 路由永久有效。

Android 在入口“修改服务器地址”更新 HTTPS 地址和端口，保留已保存观看密钥。原部署 CA 未更换时无需重装信任。仅客户端自己换 IP 不影响服务器证书，重新连接后权限仍由管理端分配。

使用稳定主机名可减少改书签，但依赖 LAN DNS/mDNS 和客户端解析。复用 Sunshine 的 Windows `DnsServiceRegister` 或 Linux Avahi 发布 `电脑名.local`，不要再加发现守护进程。访客 Wi-Fi、跨 VLAN、组播隔离及某些设备解析支持会影响可达，需实际验证；证书必须覆盖同一主机名。

## 证据与维护边界

本机新 IP 入口状态及既有独立网络实验见[部署基线](release-status.md)。已有服务器 Running/Auto、原生预检、页面 200、组件重启、整机重启和完整媒体恢复分别证明，不可相互替代。

共享宿主机的网卡切换或整机重启会影响其他开发及远程连接，须在明确维护窗口执行，保护 UE、ToDesk 和已有数据。不能用额外网卡别名冒充真实主地址迁移，不能通过修改系统信任或降低 TLS 校验获取通过结果。
